# 메모 규칙 (capture-rules)

모든 에이전트가 일하는 중에 따른다. 메모는 **다음에 더 잘하기 위한 교훈 한 문장**이다. 일지·대화 기록이 아니다.

## 1. 종류 6개

| kind | 한글 | 언제 | 제안되는 기준 |
|---|---|---|---|
| `correction` | 교정 | 주인이 내 방식을 고쳐 줬다 ("길어, 요약 먼저", "존댓말로 해") | 1번이면 그날 저녁 제안 |
| `failure` | 실패 | 명령·도구가 실패했고 **원인을 알았다** (원인 모르면 메모하지 않는다) | 같은 열쇠 2번 |
| `better_way` | 더 나은 방법 | 시행착오 끝에 되는 길을 찾았다 | 같은 열쇠 2번 |
| `wish` | 바라는 기능 | 주인이 "이런 것도 해 줘"라고 했는데 지금은 못 한다 | 제안 안 함. 주간 리포트에만 나온다 |
| `repeat_task` | 반복 작업 | 같은 종류의 일을 또 했다 | 같은 열쇠 3번 → 새 스킬 초안 |
| `user_trait` | 주인 성향(추정) | 말하지 않았지만 주인의 방식이 또 보였다 | 같은 열쇠 3번 → USER.md (추정 표시) |

헷갈리면: 주인이 직접 말했으면 `correction`, 내가 스스로 알아냈으면 `failure`/`better_way`, 주인이 말 안 했는데 보이면 `user_trait`.

## 2. 열쇠(key) 짓는 법

- 영문 소문자·숫자·하이픈, 2~64자. **무엇에 대한 교훈인지**가 보이게: `report-3line-summary`, `gmail-attach-10mb`, `weekly-sales-sheet`, `owner-numbers-first`.
- 쓰기 전에 `note.mjs --list-keys` 로 내 열쇠 목록을 본다. 같은 교훈이면 **같은 열쇠를 다시 쓴다** — 그래야 횟수가 쌓여 제안된다.
- 비슷하지만 다른 교훈이면 새 열쇠. 한 열쇠에 두 교훈을 섞지 않는다.
- 열쇠에 사람 이름·회사명·날짜를 넣지 않는다.

## 3. target 고르는 법

| 교훈이 무엇에 관한가 | target |
|---|---|
| 일하는 순서·보고 방식·확인 습관 | `AGENTS.md` |
| 도구·명령·사이트의 함정 (첨부 용량, 로그인 순서) | `TOOLS.md` |
| 말투·성격·호칭 | `SOUL.md` |
| 주인이 어떤 사람인지 (선호, 일하는 시간대) | `USER.md` |
| 이미 설치된 특정 스킬의 절차 | `skill:<스킬이름>` (예: `skill:news-summary`) |
| 반복 작업 (스킬로 만들 만한 것) | `new-skill` |

## 4. 좋은 예 / 나쁜 예

좋은 예:
- `--kind correction --key report-3line-summary --lesson "보고는 3줄 요약부터 시작하고 자세한 내용은 아래에 붙인다" --target AGENTS.md --evidence "주인: 길어, 요약 먼저"`
- `--kind failure --key gmail-attach-10mb --lesson "메일 첨부가 10MB를 넘으면 실패하므로 드라이브 링크로 보낸다" --target TOOLS.md --evidence "첨부 14MB에서 전송 실패"`
- `--kind repeat_task --key weekly-sales-sheet --lesson "매주 월요일 매출 시트를 정리해 표로 보고한다" --target new-skill --evidence "3번째 같은 요청"`

나쁜 예:
- 일지형: "오늘 오후 3시에 주인이 보고서가 길다고 해서 줄여서 다시 보냈다" → 다음에 어떻게 할지가 없다.
- 비밀 포함: "로그인 비밀번호는 abc123! 로 하면 된다" → 절대 금지. 비밀은 메모하지 않는다.
- 두 교훈 한 줄: "보고는 짧게 하고 메일은 오전에 보낸다" → 열쇠 두 개로 나눈다.

## 5. 메모하지 않는 것

- 이번 한 번만 해당하는 지시("오늘은 영어로 써 줘").
- 수습 업무(job-handoff)에서 받은 채점·교정. 그 업무 설명서로 간다(`jobs/<업무>/`). 어떤 일에서든 통하는 말투·형식·요령이면 메모한다.
- 이미 규칙 파일·스킬에 적혀 있는 것(그 규칙을 내가 어겼다면 `correction` 으로 같은 내용을 다시 메모해도 된다 — 문장을 더 분명히 할 이유가 된다).
- 비밀번호·토큰·계좌·카드번호·주민번호·연락처·고객 실명.
- 주인의 건강·종교·정치 성향·가족사·금전 사정 같은 민감한 짐작. `user_trait` 는 일하는 방식("숫자 근거부터 확인하신다")만.
- 다른 에이전트를 탓하는 말. 교훈은 "다음엔 내가 어떻게"로 쓴다.

## 6. 주인에게 말하기

- 메모했다고 매번 알리지 않는다.
- 교정을 받았을 때만 "기억해 둘게요" 한마디. 어디에 적었는지, 열쇠가 무엇인지는 말하지 않는다.
- 주인이 "방금 그거 기억해"라고 하면 `correction` 으로 메모하고 "오늘 저녁 성장 노트에서 규칙으로 올릴게요."
