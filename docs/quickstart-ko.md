# 빠른 시작 — 성장 노트 스킬

## 한 줄 요약

지금 내 비서는 **매번 처음 만난 신입처럼** 일해요. 어제 "보고는 짧게"라고 고쳐 줘도, 오늘 새 대화에서는 또 길게 씁니다.
성장 노트를 설치하면 비서가 **혼난 일·실패한 일·잘된 방법을 메모해 두고, 다음에 같은 실수를 하지 않으려는 비서**가 돼요.

## 설치하면 무엇이 달라지나요

| 이럴 때 | 지금 | 설치하면 |
|---|---|---|
| 내가 방식을 고쳐 줬을 때 ("길어, 3줄 요약부터 해") | 그 대화에서만 고치고, 다음 날 또 같은 방식 | "기억해 둘게요" 하고 메모 → 그날 밤 "이걸 규칙으로 넣을까요?" 물어봄 → 승인하면 다음부터는 알아서 그렇게 해요 |
| 오류가 났을 때 (첨부 파일이 너무 커서 메일 실패 등) | 다음에 또 같은 오류에 걸려 시간을 씀 | 원인을 메모해 두고, 같은 오류가 두 번 나면 "이렇게 피하자"를 도구 메모에 넣자고 제안 |
| "이런 것도 해 줘"라고 했을 때 | "지금은 못 해요"로 끝 | '바라는 기능'으로 적어 두고 일요일 리포트에 모아서 보여 줌 |
| 같은 일을 반복시킬 때 (매주 매출 정리 등) | 매번 처음부터 다시 설명 | 세 번째쯤 "이 일을 작업 설명서(스킬)로 만들어 둘까요?" 하고 초안을 보여 줌 |
| 말하지 않아도 보이는 내 습관 (숫자부터 확인하는 버릇 등) | 모름 | 세 번쯤 보이면 "이렇게 짐작했는데 맞나요?" 물어보고, 맞다고 하면 '주인에 대해' 메모(USER.md)에 **추정** 표시를 달아 적어 둠 |

## 비유하면

새로 들어온 신입에게 **업무 수첩**을 하나 준다고 생각해 보세요.

- 신입은 일하다 혼나거나, 실수하거나, 요령을 알게 되면 수첩에 한 줄씩 적어요.
- 같은 내용이 수첩에 자꾸 나오면, 퇴근 전에 팀장에게 "이건 **업무 매뉴얼**에 옮겨 적을까요?" 하고 물어봐요.
- 팀장이 "그래" 하면 매뉴얼에 들어가고, 다음부터는 누가 와도 그 매뉴얼대로 일해요.

여기서 수첩은 비서들의 메모, 매뉴얼은 비서의 규칙 파일과 스킬, 팀장은 **나**예요. 비서는 수첩에는 마음대로 적지만, 매뉴얼은 내가 "승인"한 것만 고쳐요.

## 매일 밤 10시, 이런 메시지가 와요

총괄 비서가 팀원들의 메모를 모아서, 고칠 만한 것만 골라 물어봐요. 새 제안은 하루 3건까지예요. 아직 답하지 않은 지난 제안이 있으면 같은 메시지에 함께 와서, 제목에 "(지난 제안 M건 포함)"이 붙고 3건보다 많아질 수 있어요.

```
🌱 성장 노트 — 오늘 개선 제안 3건

1) [업무 규칙 · 팀원 'nova']
   "보고는 3줄 요약부터 시작한다."
   이유: 오늘 한 번 고쳐 주셨어요

2) [news-summary 스킬 · 팀원 'nova']
   전: "기사 5건을 요약한다."
   후: "기사 3건을 요약하고 출처 링크를 붙인다."
   이유: 이번 주 두 번 고쳐 주셨어요

3) [주인에 대해 · 추정 · 총괄]
   "보고서를 받으면 숫자 근거부터 확인하신다."
   이렇게 짐작했는데 맞나요?
   이유: 세 번 그러셨어요

답장: "1 승인" · "2 거절" · "전부 승인" · "1 나중에"
```

**답장은 번호 + 한 마디**면 돼요.

| 이렇게 답하면 | 이렇게 돼요 |
|---|---|
| `1 승인` | 1번을 반영해요. "반영했어요" 답이 와요. |
| `2 거절` | 반영하지 않아요. 같은 제안은 2주 동안 다시 하지 않아요. |
| `전부 승인` | 메시지에 있는 제안을 모두 반영해요. |
| `1 나중에` | 그대로 둬요. 다음 날 밤 메시지에 다시 함께 와요(최대 7일). 번호는 그날 메시지 기준이라 바뀔 수 있어요. 7일이 지나도 답이 없으면 그 제안은 닫고, 다음 정리 때 새로 다듬어 다시 물어봐요. |
| `1 되돌려` · `방금 거 되돌려` | 반영한 것을 원래대로 돌려놔요. 그 사이 다른 내용이 또 바뀌었으면, 무엇이 같이 사라지는지 보여 주고 한 번 더 물어봐요. |
| `2 보여 줘` | 그 제안을 전부 보여 줘요. 새 스킬 초안은 여기서 전체 내용을 볼 수 있어요. |

"이렇게 짐작했는데 맞나요?"라고 묻는 추정 항목은, 맞으면 "3 승인"(또는 "3 맞아"), 아니면 "3 거절"이라고 답하면 돼요.

- 제안할 게 없는 날은 **아무 메시지도 오지 않아요.** 조용하면 정상이에요.
- 새 스킬을 승인하면 **시험판** 초안이 만들어져요. 총괄이 다음 대화부터 써 볼 수 있는지 확인해 줘요. 보이지 않으면 총괄에게 "새 스킬 설치 확인해 줘"라고 말하세요. 한 번 써 보고 고칠 점을 말해 주면 그것도 다시 메모돼요.

## 일요일 밤엔 이번 주 성장 리포트

일요일 밤 10시에는 이번 주 성장 리포트가 먼저 오고, 이어서 그날 제안이 올 수 있어요.

```
🌱 성장 노트 — 이번 주 성장 리포트 (11/2~11/8)

배운 점 9개 — 교정 4 · 실패 2 · 반복 작업 2 · 바라는 기능 1
반영된 개선 4건 · 거절 1건 · 대기 1건

팀원별: 총괄 3 · 'nova' 6

바라는 기능
- 인스타 댓글도 모아서 요약해 줘
```

"우리 비서가 이번 주에 이만큼 컸어요" — **목요일 발표 소재**로 그대로 쓰기 좋아요. 이어서 오는 제안에는 규칙이 많이 쌓인 곳을 합치자는 제안이 들어 있을 수 있어요.

## 효과를 키우는 법

- **고칠 때 이유도 한 마디.** "길어" 보다 "길어, 나는 폰으로 보니까 3줄 요약부터"가 훨씬 좋은 규칙이 돼요.
- **일주일에 한 번 "이번 주 뭐 배웠어?"** 라고 물어보세요. 언제든 이번 주 리포트를 보여 줘요. "성장 노트 보여 줘"는 지금까지 쌓인 현황이에요.
- **틀리게 배운 건 바로 고치기.** 이상한 규칙이 들어갔으면 "1 되돌려"(또는 "방금 거 되돌려"), 제안 단계에서 이상하면 "거절".
- 꼭 기억시키고 싶은 게 있으면 **"방금 그거 기억해"** 라고 말해 주세요.

## 꼭 알아 두세요

- **비서는 내가 승인한 것만 고쳐요.** 메모는 스스로 하지만, 규칙과 스킬을 고칠 때는 꼭 번호로 물어보고 내가 "승인"한 것만 반영해요. 고치기 전 원본은 따로 보관되니 언제든 되돌릴 수 있어요.
- **비밀번호·계좌번호 같은 건 기록하지 않도록 되어 있어요.** 비슷해 보이는 내용은 자동으로 가려요. 그래도 완벽하지는 않으니, 대화창에 비밀번호를 직접 쓰지 않는 습관이 제일 안전해요.
- **2~3주 쓰면서 고쳐 줄수록 좋아져요.** 내가 고쳐 준 것은 보통 그날 밤 바로 제안되지만, 오류나 요령은 두 번, 습관과 반복 작업은 세 번 쌓여야 제안돼요. 첫 주엔 제안이 적어도 괜찮아요.
- **팀원은 각자 메모, 총괄이 모아서 한 번에 물어봐요.** 팀원이 여러 명이어도 제안 메시지는 총괄에게서 하루 한 번만 와요. 메시지의 팀원 'nova'는 그 규칙이 어느 비서의 것인지 알려 줘요.

## 설치

OpenClaw가 돌아가는 컴퓨터(서버)의 터미널에 한 줄씩 붙여 넣으세요. 두 번째 줄은 총괄용, 세 번째 줄은 **팀원마다 한 번씩** 반복해요. `<팀원 id>` 자리에는 영문 id를 넣으세요. `openclaw agents list`에 나오는 왼쪽 영문 값이에요.

```bash
git clone https://github.com/IrumHahn/openclaw-self-improve.git
openclaw skills install ./openclaw-self-improve/skill/self-improve --as self-improve --agent main
openclaw skills install ./openclaw-self-improve/skill/self-improve --as self-improve --agent <팀원 id>   # 팀원마다 한 줄씩
node ./openclaw-self-improve/scripts/install_hook.mjs --all-agents
```

마지막 줄은 비서 모두의 업무 규칙(AGENTS.md)에 "일하면서 배운 점 메모하기"를 넣어요. 원래 파일은 따로 백업돼요.

그다음 총괄 비서에게 이렇게 말하세요.

> **성장 노트 시작해 줘**

총괄이 알림 시각(매일 밤 10시, 일요일은 주간 리포트부터)과 받을 채널을 확인한 뒤 알림 두 개를 등록하고, 등록한 시각과 채널을 알려 줘요.

## 첫날 해 볼 것 3가지

1. **일부러 한 번 고쳐 주기.** 팀원 비서에게 보고를 시키고, 길게 오면 "길어, 3줄 요약부터 해 줘"라고 고쳐 주세요. "기억해 둘게요"라는 답이 오면 메모된 거예요.
2. **밤 10시 제안 받아 보기.** 🌱 메시지가 오면 1번에 "1 승인"이라고 답하세요. 밤까지 기다리기 싫으면 총괄에게 "성장 노트 저녁 정리 지금 해 줘"라고 하면 바로 와요.
3. **승인과 되돌리기 해 보기.** 승인한 다음 같은 비서에게 다시 보고를 시켜서 3줄 요약부터 하는지 보세요. 그다음 "1 되돌려"라고 해서 원래대로 돌아가는 것도 한 번 확인해 보세요. 되돌린 규칙을 다시 원하면 한 번 더 고쳐 주세요. 다음 정리 때 다시 제안돼요.

## 자주 묻는 질문

**알림이 안 와요.**
먼저, 제안할 게 없는 날은 원래 조용해요. 총괄에게 "성장 노트 보여 줘"라고 해서 배운 점이 쌓이고 있는지 보세요. 쌓이는데도 안 온다면 "성장 노트 알림 등록돼 있어?"라고 물어보세요. 등록된 시각과 채널을 확인해 줘요. 아예 없으면 "성장 노트 시작해 줘"를 다시 하면 돼요.

**이상한 규칙이 들어갔어요.**
방금 승인한 거라면 "방금 거 되돌려", 메시지 번호를 알면 "1 되돌려"라고 하세요. 예전에 들어간 거라면 "보고서 숫자 규칙 빼 줘"처럼 내용으로 말해 주세요. 총괄이 어떤 규칙인지 보여 주고 확인받은 뒤 되돌려요. 그 뒤 내가 직접 그 파일을 고쳤다면, 무엇이 같이 사라지는지 먼저 보여 주고 한 번 더 물어봐요.

**팀원이 메모를 안 하는 것 같아요.**
세 가지를 확인해 보세요. ① 설치할 때 그 팀원에게도 스킬 설치 줄(세 번째 줄)을 실행했나요? ② 마지막 줄(`install_hook`)을 실행했나요? ③ 고칠 때 그 팀원에게 직접 말했나요? 메모는 고침을 받은 비서가 해요. 확실하게 하려면 그 팀원에게 "방금 그거 기억해"라고 말해 주세요.

**끄고 싶어요.**
총괄에게 "성장 노트 꺼 줘"라고 하면 저녁 알림 두 개를 꺼 줘요. 지금까지 쌓인 메모와 이미 반영된 규칙은 그대로 남아요. 완전히 빼고 싶으면 터미널에서 아래 줄을 실행해 업무 규칙에 넣었던 메모 안내를 지우세요.

```bash
node ./openclaw-self-improve/scripts/install_hook.mjs --all-agents --remove
```

그다음 각 비서에 설치된 성장 노트 스킬 폴더(`self-improve`)를 지우면 끝이에요. 폴더가 어디 있는지 모르겠으면 총괄에게 "성장 노트 스킬 폴더 어디 있어?"라고 물어보세요. 지금까지 쌓인 메모(각 비서 작업 폴더의 `learnings` 폴더)와 이미 반영된 규칙은 지우지 않고 남겨 둬요.
